# SGLang 的 CUDA 12.9 构建

此分支将 SGLang v0.5.23 适配到 CPython 3.11 / 3.12、Torch `2.13.0+cu129`，保留上游多架构配置；本机验证使用 NVIDIA L20（SM89）。这是 CUDA 12 的专用构建。主包版本为 `0.5.23+cu129`，AOT kernel 版本为 `0.4.10+cu129`。

## 环境要求

- Linux x86_64、Python 3.11 或 3.12；本机为 glibc 2.32，发布 CI 使用 glibc 2.28 构建镜像。
- CUDA Toolkit 12.9、支持 C++20 的编译器，以及 Rust 1.99.1。首次推理仍可能即时编译 CUDA 内核，因此运行环境也需要 nvcc 和可用的 host compiler。
- 可运行 CUDA 12.9 的驱动环境。本机内核驱动保持 `535.161.08`，通过独立的 CUDA 12.9 forward-compat 用户态库 `575.57.08` 运行；wheel 不安装驱动或兼容库。

`nvidia-smi` 显示的 CUDA 版本不是已安装的 Toolkit 版本，也不能代替实卡验证。SM89 仍受 CUDA 13 支持；选择 cu129 是本分支的驱动和依赖适配方案。

## 本机构建

先创建并激活独立环境，配置 CUDA 12.9、编译器和兼容库路径。以下命令要求 `CUDA_HOME`、`CC`、`CXX`、`NVCC_CCBIN` 和 `LD_LIBRARY_PATH` 已对应你的工具链；不要将 nvcc 的 stub 驱动库放进运行时搜索路径。

```bash
uv venv --python 3.11 .venv-sm89
source .venv-sm89/bin/activate
uv pip install torch==2.13.0+cu129 --index-url https://download.pytorch.org/whl/cu129
uv pip install build wheel setuptools-rust 'setuptools-scm>=8' \
  'scikit-build-core>=0.10' 'cmake>=3.31,<4' ninja patchelf
python scripts/build_cu129.py
uv pip install --find-links build/cu129/dist \
  --extra-index-url https://download.pytorch.org/whl/cu129 \
  --index-strategy unsafe-best-match \
  'sglang==0.5.23+cu129'
uv pip check
```

构建入口为当前 checkout，编译全部五个 Rust 扩展及 AOT kernel，移除 ELF 中的绝对构建 RPATH，并写出 `build/cu129/dist/SHA256SUMS` 和 `build-manifest.json`。可通过 `CMAKE_BUILD_PARALLEL_LEVEL`、`CARGO_BUILD_JOBS`、`MAX_JOBS` 和 `NVCC_THREADS` 调整并行度；本地默认并行度为 2。

本次本地构建复用了已校验 SHA256 的官方依赖 wheel 和固定提交的第三方源码缓存，重新编译当前分支源码。独立环境的本机激活入口保存在未提交的 `build/cu129/activate.sh`；它包含这台机器的 SDK、兼容库及编译器配置。

## 运行模型

先激活环境并选择空闲 GPU，再启动服务。下面使用 Qwen3-0.6B，单卡 FP16，默认自动选择 attention 后端并启用 CUDA Graph。

```bash
source build/cu129/activate.sh
export CUDA_VISIBLE_DEVICES=0
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-0.6B \
  --dtype float16 --tp-size 1 \
  --context-length 4096 --max-total-tokens 8192 \
  --max-running-requests 4 --mem-fraction-static 0.25 \
  --sampling-backend pytorch --host 127.0.0.1 --port 30000
```

```bash
curl http://127.0.0.1:30000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"Qwen/Qwen3-0.6B","messages":[{"role":"user","content":"What is 2 + 2?"}],"temperature":0,"max_tokens":32,"chat_template_kwargs":{"enable_thinking":false}}'
```

已有本地模型时，将 `--model-path` 替换为模型目录。运行过程中的 JIT 需要能够找到 CUDA 12.9 和对应的 C++ 编译器。

## GitHub 发布

工作流 `.github/workflows/release-cu129.yml` 分别为 CPython 3.11、3.12 构建，在此分支相关文件变更时触发，也支持手动触发。它使用固定 digest 的 CUDA 12.9 / manylinux2_28 镜像构建，上传日志和产物，并在构建及元数据检查成功后创建 GitHub prerelease。

Release 包含每个 Python 版本的两个 wheel、SHA256 校验文件及构建清单；标签格式为 `v0.5.23-cu129-<run_number>-<run_attempt>`，指向实际构建的提交。普通 GitHub runner 没有 GPU，CI 编译成功不能代替 L20 实卡推理验证；发布步骤还要求同一提交的 `L20 inference / cu129` 状态通过。

完整多架构构建按对象文件分成 8 个并行任务，再统一链接并交给原有 wheel 后端打包。汇总时校验全部分片的提交、Python 版本、编译命令及对象 SHA256，不删减上游架构或内核。

## 支持范围

FA3 和 FlashMLA 保留上游构建配置；它们各自的硬件限制仍然适用。DeepGEMM 及较新 GPU 专用后端不属于本分支的 L20 推理支持范围。多卡、MoE、量化及多模态需要另行验证；A10（SM86）可以使用上游保留的 SM80 cubin，但其驱动或虚拟化层仍需独立满足 CUDA 12.9 的要求，尚未在该硬件验证。
